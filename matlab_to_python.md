## Corrections required (things the draft plan gets wrong or misses)

### 1. `AjusTramElas` has 11 columns, NOT 5 — the pre-allocation bug matters

The draft plan's `ske.py` docstring says the output array is `shape (n_loops, 11)`,
which is correct. But the MATLAB code on line 418 pre-allocates only 5 columns:

```matlab
AjusTramElas = nan(size(tramoselasticos, 1), 5);
```

The loop then writes columns 1–11. For single-point elastic segments (`length(tempy3)==1`),
the code hits `disp('aqui')` and skips all writes — leaving columns 1–11 as `NaN`
for that row. The Python translation must pre-allocate `np.full((n_periods, 11), np.nan)`
from the start, and handle the single-point case explicitly with a `continue` or a
`skip_row` flag. Do NOT replicate the 5-column pre-allocation; it is a MATLAB bug.

### 2. The `ske_ponderado` formula has a subtle bug in the MATLAB code

Line 474:
```matlab
ske_ponderado = sum(AjusTramElas2(:,11).*AjusTramElas2(:,8)) /
                sum(AjusTramElas2(:,8).*AjusTramElas2(:,10));
```

`AjusTramElas2` is already filtered to accepted rows only (line 471 deletes
rejected rows), so `AjusTramElas2(:,10)` is all 1s. The denominator is therefore
just `sum(AjusTramElas2(:,8))` — the sum of y-amplitudes of accepted loops.
Numerator is `sum(ske * amplitude)`. This is correct amplitude-weighted mean.

**Python translation:** Since you are not deleting rows (you will use a mask),
the correct Python formula is:

```python
mask = AjusTramElas[:, 9] == 1  # col index 9 = accepted flag (0-based col 10 in MATLAB)
ske_weighted = (np.sum(AjusTramElas[mask, 10] * AjusTramElas[mask, 7]) /
                np.sum(AjusTramElas[mask, 7]))
# col 10 (0-based) = s_ke; col 7 (0-based) = y-amplitude
```

The draft plan's `aggregate_ske_stats` function must use this masked form, not
replicate the delete-row approach.

### 3. The `intervalo_y` default is NOT a fraction — it is an absolute value in metres

The draft plan's `config.py` says:
```
INTERVALO_Y_FRACTION = 0.05   # 5% of GW depth range
```

This is wrong. In the MATLAB code, `intervalo_y` defaults to `20` (metres,
absolute GWL depth threshold, line 121) and `intervalo_x` defaults to `1e-2`
(metres, absolute displacement threshold, line 122). These are not fractions of
any range. For our 2S-TOOL inputs (GWL depth ~5–30 m, displacement ~0.01–0.2 m),
the auto-parameter logic in `prepare_2stool_inputs.py` already writes station-
specific values into the MATLAB `.xlsx` — the Python translation must read those
values from the same Excel sheet's `InputData` tab (col F), not use hardcoded
fractions. If that tab is absent, fall back to:

```python
INTERVALO_Y_DEFAULT = 20.0   # metres absolute
INTERVALO_X_DEFAULT = 0.01   # metres absolute
HP_INICIAL_DEFAULT = None    # → computed as max(y1) if not supplied
PORCENTAJE_DEFAULT = 0.2
```

### 4. `hp_inicial` (pre-consolidation head) defaults to `max(y1)`, not `330`

The MATLAB dialog default on line 99 is `'330'` — a hardcoded example from the
paper's test dataset (Béjar 2017, with ~330 m deep water table). For our Taiwan
dataset (5–30 m deep), this default is physically meaningless.

The correct physical default for unknown pre-consolidation history is:
```
hp_inicial = max(y1)
```
This is the deepest observed GWL — the natural starting point when no historical
maximum is known. The Python `config.py` should set:
```python
HP_INICIAL_DEFAULT = None   # → replaced at runtime by max(y1)
```
and `pipeline.py` should apply `hp_inicial = hp_inicial or float(np.max(y1))`.

### 5. `encadenado=1` block — the `TempInputFile` mechanism

The MATLAB script starts with `load TempInputFile`, which loads `path` and `file`
from a `.mat` file written by Part 1. The Python translation eliminates this
correctly (direct CLI argument). But the `io_utils.py` docstring in the draft
plan says it reads **columns B and C (index 1 and 2)**. The actual MATLAB reads:

```matlab
datos = readmatrix([path file], 'Sheet', 'StrainStress', 'Range', 'B2');
x1 = datos(:,1);   % col B = displacement
y1 = datos(:,2);   % col C = GWL depth
```

`Range='B2'` means: start at cell B2, read rightward. So column indices in the
resulting matrix are 0 and 1 (0-based). The draft plan's `index 1 and 2` is
1-based Excel column indices, which is confusing notation — clarify in code as:

```python
sheet = pd.read_excel(filepath, sheet_name='StrainStress', header=None)
x1 = sheet.iloc[1:, 1].dropna().to_numpy(dtype=float)  # col B, skip row 1
y1 = sheet.iloc[1:, 2].dropna().to_numpy(dtype=float)  # col C, skip row 1
```

### 6. The `n2 < 2` early-exit condition is not in the MATLAB code

The draft plan says `apply_x_criterion` returns `n2 < 2` as an early-exit guard.
The actual MATLAB does not have this guard — it proceeds regardless. What IS in
the code is an implicit risk: if `findpeaks` returns 0 or 1 peaks, subsequent
index operations on `imax_ini` fail. The Python translation should add this guard
explicitly (it is a defensive improvement over MATLAB, not a translation of
existing logic). Flag this clearly in code comments so it is not mistaken for
a faithful translation of MATLAB behaviour.

Line 368:

```matlab
    disp('aqui')
end
```

This is a debugging artifact left in the published code. Do not translate it.
Remove it silently.

### 8. The `ske_aceptados` computation and `ske_std` edge case

Lines 480–482:
```matlab
temp1 = AjusTramElas(:,11) .* AjusTramElas(:,10);
ske_aceptados = temp1(find(temp1~=0));
ske_std = std(ske_aceptados);
```

If only one loop is accepted, `ske_std = 0` in MATLAB (by convention). The
Python `np.std` with `ddof=0` also returns 0 for a single value, so behaviour
matches. But the Figure 3 text annotation branches on `sum(accepted)==1` to
suppress the sigma display (line 557). The `aggregate_ske_stats` dict must
include `n_accepted` so `visualize.py` can apply this branch.

### 9. Figure 3 text positioning uses `javi` — do not try to replicate exactly

Lines 550–566 compute legend and text positions using MATLAB figure-units
arithmetic (`hl.Position`, `javi = hl.Position(1) + hl.Position(3)`). This
is MATLAB GUI layout logic that has no clean matplotlib equivalent. In Python,
use a fixed `ax.text(0.98, 0.08, ..., transform=ax.transAxes,
ha='right', va='bottom', bbox=dict(boxstyle='square', fc='white'))`. Visual
output will be equivalent. Do not attempt to translate the `javi` arithmetic.

### 10. CSV output columns must match MATLAB exactly for `collect_2stool_results.py`

Our existing `collect_2stool_results.py` reads `_summary.csv` and `_loops.csv`.
The Python translation must write these with the same column names and row
structure as the MATLAB output. The MATLAB writes to Excel (not CSV directly),
but `collect_2stool_results.py` was written to expect:

- `_summary.csv`: one row, columns `skv`, `ske_weighted`, `n_loops_accepted`
- `_loops.csv`: one row per elastic period, columns include `ske`, `n_points`,
